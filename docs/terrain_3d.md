# 3D-рельєф Jezero

## Що реалізовано

Перемикач **2D карта / 3D рельєф** у React. Three.js/WebGL рендерить справжні
висоти із вибраного CTX або HiRISE DEM, а не вигадану поверхню.
Є орбітальна камера, обертання, масштаб, панорама, вигляд згори, скидання та fullscreen.
Управління доступне також кнопками. Натискання по видимій поверхні вибирає A/B;
координати додатково перевіряються звичайним API висот.

Маршрут A* відображається в 3D, але розрахунок залишається на первинній сітці.
Перемикання 2D/3D не видаляє маршрут. Зміна dataset, координат чи параметрів маршрутизації
очищає його, як і в 2D. Камера зберігає ракурс при оновленні маршруту/кольорів.

## API display mesh

`GET /api/terrain/mesh?dataset=ctx&max_size=260`

- `max_size`: 20…260; відповідь обмежена приблизно 261 × 261 вершинами.
- Повертаються вихідні індекси рядків/стовпців, справжні висоти, ухили, позиції та індекси трикутників.
- CTX 250 × 250 при 260 передається без проріджування.
- HiRISE 1000 × 1000 проріджується до сітки приблизно 251 × 251.
- Регіональний CTX 1513 × 1515 проріджується для display до приблизно 254 × 254;
  A* та висоти використовують повну native 20м сітку. Текстура — регіональна CTX,
  а не розтягнутий старий 5км фрагмент.
- Якщо навіть несемпльована первинна NoData-клітинка лежить у межах coarse quad,
  відповідні трикутники **не створюються**. Не інтерполюємо поверх великої невідомої ділянки.
- X — схід у локальних сферичних метрах із корекцією `cos(latitude)`,
  Z — південь, Y — висота відносно явно повернутого `elevation_origin_m`.
  Використано радіус Марса 3 396 190 м, не Землі.

Відсутня висота повертається `null`. Технічні координати невикористаних invalid vertices
не є вимірюваннями; вони не входять у жоден трикутник.

## Текстура, кольори та масштаб

Оптика — справжній CTX overlay (native 6 м), прив’язаний до марсіанських lon/lat.
HiRISE DEM не перетворює цю текстуру на метрову фотографію.
Перемикачі висот/ухилів вмикають забарвлення за відповідними вимірюваннями.
Геологія та полігони науки лишаються в 2D; кнопка наукової картки повертає карту в 2D.

Базова вертикальна шкала **×1**. Візуальні ×3/×8 явно підписані, не змінюють висоти
в масивах, ухили, A*, blocked mask, профіль або експорт. Візуальний маршрут/маркери
трохи підняті над поверхнею для читабельності; це не фізична висота шляху.

## Перевірка та ресурси

```powershell
python -m unittest discover -s tests -v
python tests/smoke_3d_browser.py
```

У Chromium фактично перевірено CTX/HiRISE, рендеринг WebGL, маршрут, обертання,
×3, повернення до 2D, raycast-вибір точки через API та mobile layout.
Звіт: `artifacts/mvp/3d_e2e_report.json`, зображення — `terrain-3d-ctx.png` і `terrain-3d-hirise.png`.

Three.js завантажується lazy chunk лише при відкритті 3D. Rendering відбувається
при зміні камери/даних, а не у нескінченному idle-циклі. Geometry, textures, controls
та WebGL-контекст звільняються при перемиканні. Якщо WebGL недоступний, є явне
повідомлення й повернення до 2D; браузерні security flags не послаблюються.
