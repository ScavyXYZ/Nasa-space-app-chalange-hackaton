# ТЕХНІЧНЕ ЗАВДАННЯ

## MARS EXPLORER — MVP v1.0

**Проєкт:** NASA Space Apps Challenge 2026
**Challenge:** Interplanetary Survival Guide: Martian Map
**Тип продукту:** інтерактивний вебзастосунок
**Команда:** 6 учасників
**Термін розробки:** 14–15 листопада 2026 року
**Територія дослідження:** кратер Jezero, Марс

---

## 1. Мета проєкту

Розробити вебплатформу для планування дослідницьких маршрутів на поверхні Марса, яка об'єднує наукові дані NASA, дозволяє аналізувати рельєф, переглядати геологічні об'єкти та будувати маршрути з урахуванням характеристик місцевості.

**Головна проблема:** інформація про Марс розподілена між різними місіями та джерелами. Для планування експедиції необхідно об'єднати ці дані в одному інструменті.

**Наше рішення:** багатошарова інтерактивна карта з модулем аналізу поверхні та планування Marswalk.

## 2. Основний сценарій роботи

Після відкриття сайту користувач повинен мати можливість:

1. Переглянути карту вибраного району Марса.
2. Увімкнути потрібні наукові шари.
3. Дослідити висоти, схили та геологічні об'єкти.
4. Вибрати початкову та кінцеву точки експедиції.
5. Натиснути кнопку **Build Route**.
6. Отримати маршрут, розрахований алгоритмом A\*.
7. Переглянути відстань, перепади висот і потенційно складні ділянки.
8. Побачити наукові об'єкти поблизу маршруту.

Цей сценарій є основою демонстрації для журі.

## 3. Обов'язковий функціонал MVP (P0)

### 3.1. Інтерактивна карта Марса

Реалізувати:

- Карту вибраної території Jezero Crater.
- Масштабування та переміщення.
- Відображення координат курсора або обраної точки.
- Вибір початкової та кінцевої точок.
- Перемикання картографічних шарів.
- Відображення маршруту та наукових об'єктів.

**Результат:** повністю інтерактивна карта, доступна у браузері.

### 3.2. Наукові шари NASA

Інтегрувати три типи даних:

**Шар 1 — Optical Imagery**

Супутникові зображення поверхні Марса з NASA Mars Trek / CTX.

**Шар 2 — Topography**

Цифрова модель висот DEM, отримана з наукових даних NASA.

**Шар 3 — Geology**

Геологічні дані USGS для досліджуваної території або науково підтверджені геологічні об'єкти, якщо детальна карта недоступна.

Кожен шар повинен мати назву, легенду та посилання на джерело.

**Результат:** користувач може досліджувати територію за декількома науковими характеристиками.

### 3.3. Аналіз рельєфу

На основі DEM реалізувати:

- Отримання висоти поверхні.
- Обчислення крутизни схилів.
- Карту ухилів.
- Виділення ділянок із високою крутизною.
- Обчислення перепаду висот уздовж маршруту.

Поріг ухилу налаштовується в програмі. Значення порога є параметром нашої моделі, а не офіційним обмеженням NASA.

**Результат:** система визначає складність місцевості за доступними топографічними даними.

### 3.4. Алгоритм пошуку маршруту

Реалізувати алгоритм **A\*** на CPU (Python).

Вхідні дані:

- Початкова точка.
- Кінцева точка.
- Карта висот.
- Карта ухилів.
- Параметри маршрутизації.

Алгоритм повинен:

1. Перетворювати досліджувану територію на сітку.
2. Враховувати відстань між клітинками.
3. Застосовувати штраф за круті схили.
4. Виключати непрохідні за обраним порогом клітинки.
5. Знаходити маршрут із мінімальною модельною вартістю.
6. Повертати координати маршруту.

**Результат:** маршрут, який можна відобразити на карті та перевірити за характеристиками рельєфу.

### 3.5. Аналіз маршруту

Після побудови маршруту показати:

- Загальну відстань (м або км).
- Мінімальну й максимальну висоту.
- Загальний набір висоти.
- Максимальний ухил.
- Графік висоти вздовж маршруту.
- Ділянки, що потребують додаткової перевірки.

**Результат:** користувач розуміє, чим характеризується побудований маршрут.

### 3.6. Наукові точки інтересу

Додати мінімум три реальні наукові об'єкти у вибраній території.

Кожна точка повинна містити:

- Назву.
- Координати або географічну область.
- Короткий науковий опис.
- Причину дослідницького інтересу.
- Джерело NASA / USGS.
- Фотографію, якщо є підтверджена прив'язка.

**Результат:** користувач може планувати не лише переміщення, але й наукові дослідження.

### API

**GET /api/health**

Перевірка роботи сервера.

**GET /api/layers**

Список наукових шарів та їхні метадані.

**GET /api/points**

Список наукових об'єктів.

**GET /api/elevation**

Отримання висоти для заданих координат.

**POST /api/route**

Побудова маршруту.

Приклад запиту:

```json
{
  "start": {"lat": 18.4, "lon": 77.5},
  "end": {"lat": 18.42, "lon": 77.52},
  "max_slope_deg": 15
}
```

API повертає маршрут у GeoJSON та розраховані характеристики. Координати в прикладі умовні.

## 7. Наукові вимоги та обмеження

- Використовувати справжні дані NASA / USGS.
- Зберігати інформацію про походження кожного набору даних.
- Використовувати марсіанську геометрію для розрахунку відстаней.
- Не підміняти відсутні вимірювання вигаданими числами.
- Не використовувати низькодетальну MOLA як доказ відсутності дрібних перешкод.
- Розрізняти спостережувані дані та результати математичної моделі.
- Позначати невідомі й недоступні області DEM.
- Не називати маршрути гарантовано безпечними.

**Продукт є дослідницьким прототипом, а не системою реальної навігації астронавтів.**

## 9. Критерії готовності MVP

Проєкт вважається завершеним, якщо:

- [ ] Вебсайт відкривається в браузері.
- [ ] Відображається реальна карта частини Марса.
- [ ] Є три типи наукової інформації.
- [ ] Можна переглядати висоти та ухили.
- [ ] Можна вибрати старт і фініш.
- [ ] Алгоритм A\* будує маршрут.
- [ ] Маршрут відображається на карті.
- [ ] Показуються характеристики маршруту.
- [ ] Є графік висот.
- [ ] Є мінімум три наукові точки.
- [ ] Усі дані мають джерела.
- [ ] Є публічне демо та README.

### Мінімальний демонстраційний сценарій

**Відкрити сайт → вибрати точки на Марсі → увімкнути наукові шари → побудувати маршрут → переглянути аналіз рельєфу → дослідити наукові об'єкти.**

Це основна функціональність, яка обов'язково повинна працювати до презентації.

## 10. Додати, якщо буде час (P1/P2)

Наведені функції **не є обов'язковими для MVP** і реалізуються лише після завершення та тестування основної системи.

### GPU Acceleration

- Використати CuPy для обробки великої DEM.
- Прискорити розрахунок ухилів та побудову карт складності.
- Порівняти продуктивність NumPy (CPU) і CuPy (GPU).
- Додати графік часу виконання обчислень.

GPU-версія не повинна замінювати робочий CPU-алгоритм A\* без підтвердженого прискорення та перевірки результатів.

### 3D Mars Terrain

- Створити тривимірну модель вибраної території.
- Відображати побудований маршрут у 3D.
- Додати зміну кута огляду та масштабування.

### Advanced Mission Planning

- Порівняння двох альтернативних маршрутів.
- Додавання декількох наукових зупинок.
- Орієнтовний розрахунок часу експедиції.
- Експорт маршруту в GeoJSON.
- Генерація PDF-звіту.

### Additional NASA Layers

- Температурні дані THEMIS.
- Детальні зображення HiRISE.
- Фотографії Perseverance.
- Додаткові геологічні та мінералогічні шари.

### Інтелектуальні можливості

- Автоматичний пошук цікавих геологічних об'єктів.
- Рекомендації наукових точок поблизу маршруту.
- Оцінювання альтернативних шляхів за декількома критеріями.

**Пріоритет розширень:** спочатку порівняння маршрутів, потім 3D, далі GPU та додаткові наукові функції.
