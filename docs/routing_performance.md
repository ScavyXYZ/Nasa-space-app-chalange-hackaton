# Швидкодія маршрутизації

## Що змінено

Для регулярних марсіанських сіток A* тепер використовує нижню оцінку вартості
восьмисусіднього шляху через глобальні мінімуми довжин горизонтальних,
вертикальних і діагональних ребер. Це точний пошук у вихідній сітці, не
downsampling, не weighted A* і не маршрут у вузькому наближеному коридорі.
Для стороннього `GridGeometry` без `lower_bound_m` лишається стара оцінка.

Оцінка є вартістю шляху у послабленому графі: усі перешкоди і штрафи ігноруються,
а кожен тип ребра не дорожчий за справжній. Тому вона не перевищує оптимальної
вартості та є узгодженою. Для анізотропних сіток осьові вартості додатково
обмежуються мінімальною діагональною вартістю.

Вартість реальних ребер, марсіанська геометрія, NoData, поріг ухилу, перевірка
перепаду висот і заборона зрізання кутів **не змінені**. Дані не змінені.

## Вимірювання

```powershell
python scripts/benchmark_routing.py --repeats 5 --output artifacts/mvp/routing_benchmark.json
```

Локальний Windows/Python 3.14, медіана п’яти пошуків з чергуванням порядку:

| Сценарій | Стара евристика | Нова евристика | Прискорення |
|---|---:|---:|---:|
| CTX локально | 10,35 мс | 4,62 мс | 2,24× |
| HiRISE | 46,43 мс | 20,58 мс | 2,26× |
| CTX регіон, ~24 км | 5,40 с | 2,46 с | 2,20× |

Координати клітинок, вартості та кількість розгорнутих клітинок — у JSON-звіті.
На регіональному прикладі: 224 977 → 130 509 клітинок, вартість однакова.
Це **тільки CPU search**, не повна HTTP-відповідь: підготовка геометрії, аналіз
наукових областей і серіалізація не входять. Результат не гарантує такого
прискорення для будь-яких точок чи іншого обладнання.

Додано перевірки узгодженості нижньої оцінки на трьох справжніх геометріях
та порівняння вартості A*/hierarchical із незалежним Dijkstra на fixtures.

## Чому поки не GPU

GPU-backend **не реалізований**. Купа пріоритетів A* та нерегулярне розширення
вузлів не переносяться на GPU простим замінюванням NumPy на CuPy. Копіювання
сітки та синхронізація можуть звести виграш нанівець, особливо для одного запиту.
WebGL-глобус і 3D вже рендеряться на GPU, але це не прискорення backend A*.

Наступні кандидати: кеш незмінної геометрії з контрольованим життєвим циклом,
профілювання аналізу геології, compiled CPU kernel; потім окремий GPU-прототип
із вимірюванням end-to-end часу, RAM/VRAM і перевіркою точного результату.
GPU не повинен бути обов’язковим для запуску застосунку.
