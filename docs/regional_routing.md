# Шкала та маршрути по всій регіональній карті

## Що змінилося

Раніше оптика охоплювала ~32 × 30 проєкційних км, а робочий DEM — тільки 5 × 5 км.
Тепер окремий **`regional` dataset** покриває **весь прямокутник регіональної CTX-оптики**.
Вибирається за замовчуванням як «CTX регіон / 20 м · уся карта».
Оригінальні `ctx` 5км і локальний `hirise` залишені без зміни для сумісності.

Розміри різних проєкцій не можна порівнювати як одну й ту саму фізичну відстань:
оптика має стандартну паралель 0°, DEM — 18.4663°. Підготовлений DEM має
**30.3 × 30.26 проєкційних км**, а місцеві фізичні X-відстані відрізняються
на косинус широти, врахований у похідних і геодезичних відстанях.

## Справжні дані та перевірки

- Джерело: той самий незмінений USGS Science Investigation CTX DEM 20м.
- Вікно оригіналу: col=458, row=1686, width=1515, height=1513.
- Плюс однопіксельний native halo для похідних на краях.
- 1513 × 1515 = **2 292 195** клітинок, **100% валідні висоти й ухили**.
- Не застосовували перепроєкцію DEM, інтерполяцію висот чи заповнення пропусків.
- Ухили перераховані в локальних метрах Марса з широтною корекцією масштабу.
- GeoTIFF/NumPy/masks/metadata/overlays/report: `data/processed/regional/`.
- Первинні 5км продукти не переписані.

```powershell
python scripts/prepare_regional_terrain.py
python scripts/prepare_runtime_data.py
python -m unittest discover -s tests -v
python tests/smoke_regional_browser.py
```

При повторній підготовці зупиніть backend, щоб не перезаписати відкриті mmap-масиви.

## Геологія

У ширшому AOI відібрано **315 вихідних полігональних об’єктів** SIM 3464
і **12 вихідних назв геологічних областей**. Серед назв джерело має обидва
написання `Crater rim unit` та `Crater riim unit`; їх не виправляли й не видаємо
за підтверджені дві різні стратиграфічні одиниці.

Повна геометрія та первинні FID/атрибути залишені у неспрощених GeoJSON.
Окремі `*_display.geojson` мають topology-preserving **15м** спрощення у
марсіанських проєкційних метрах, щоб не передавати у браузер ~56МБ зайвих координат.
Аналіз близькості маршруту виконується на **повній** геометрії, не на display.
USGS registration uncertainty 100–200м не зникає.

## Масштаб карти

У нижньому лівому куті є **«Відстань на Марсі»**, шкала в метрах/кілометрах.
`L.control.scale` використовує `map.distance` із нашим Mars CRS
(сфера радіуса 3 396 190м), **не земну сферу Leaflet**.
Шкала оновлюється при наближенні, віддаленні, панорамуванні та fullscreen.

У незалежній браузерній перевірці масштаб `3 km` мав ширину, яка відповідала
приблизно **3001.5м** за географічною прив’язкою оптики й марсіанською сферою.
Різниця ~0.05% — округлення display pixels; земна шкала дала б суттєво інший результат.

## API та реальні маршрути

```json
{
  "dataset": "regional",
  "start": {"lon": 77.38, "lat": 18.3836},
  "end": {"lon": 77.55, "lat": 18.3836},
  "max_slope_deg": 25
}
```

`POST /api/route` приймає цей payload. Обидві точки поза початковим 5км AOI;
приклад ~10км перевірено через React/браузер. API/unit-тест також фактично
будує приблизно **24км** шлях між іншими точками поза старим AOI.
Діє той самий A*: slope/grade restrictions, NoData та заборона corner cutting.

Для довгих запитів піднято бюджет до 20с / 500 000 expansions.
`search_limit` відрізняється від `no_route`. Бюджет не є жорстким SLA HTTP:
підготовка графа й аналіз геології також займають час.

**«По всій карті» не означає «гарантовано між будь-якими двома точками».**
Крутий схил чи обраний поріг можуть цілком законно заблокувати шлях.
І це не глобальна маршрутизація по всьому Марсу: глобус лишається оглядовим.
