# Стан MVP — перевірені факти

**Поточний демореліз 15.11:** [release_status.md](release_status.md).
Наведений нижче блок Global Mission Control описує попередній 4 ppd етап;
нині runtime використовує **16 ppd / 0,0625° / ~3,7 км**, єдиний 2D-атлас,
USGS-геологію, автовибір CTX, зупинки, політ, звіт і QR.
Актуальний unit/API набір: **53 тести**.

## Оновлення: Global Mission Control

- Новий початковий інтерфейс із планетарним оглядом, адаптивним планувальником,
  каталогом місць, топографічною легендою та профілем із клавіатурним керуванням.
- Реальні глобальні MOLA-висоти 720 × 1440 (0,25°), counts і походження з NASA PDS.
- Coarse-to-fine spherical weighted A*: циклічна довгота, полярні переходи,
  уточнення на нативній сітці, бюджет 12 с, до двох одночасних глобальних запитів.
- Порівняння стратегій, GeoJSON, збереження плану в браузері,
  утримання глобального та локального планів при перемиканні режимів.
- Глобальна топографія/рельєф і деталізований Jezero — окремі моделі.
  Автоматичного зшивання MOLA з CTX/HiRISE та GPU routing немає.
- Документація: [global_explorer.md](global_explorer.md).
- Перевірено локально: **49 Python-тестів**, production build, шість браузерних
  сценаріїв (mission, globe, MVP, 3D, regional, planner). JS page errors: 0.
- Нові скриншоти й E2E-звіт: `artifacts/global/`.

## Готово локально

- React 19 + TypeScript + Vite + Tailwind CSS.
- Leaflet-карта з локальною реальною CTX-оптикою, висотами, ухилами, геологією й областями науки.
- Регіональна CTX-оптика (~32 × 30 км) для контексту, дробовий zoom, обмеження виходу за покриття та кнопка повернення до DEM. Це не розширює покриття маршрутизації.
- Збільшена робоча карта, згортання панелі планування, native fullscreen та кнопки огляду регіону/маршруту. Параметри й точки зберігаються при згортанні.
- Three.js 3D-рельєф за справжніми DEM, CTX-текстура, маршрут на поверхні, вибір A/B, обертання/масштаб/вигляд згори. ×1 за замовчуванням, ×3/×8 — явно позначене візуальне підсилення.
- Глобус усього Марса як початковий режим: офіційна колоризована Viking MDIM 2.1 мозаїка NASA Ames/USGS, координати, обертання, zoom/fullscreen і перехід до Jezero.
- A/B на довільних точках глобуса; глобальний пошук MOLA й детальний пошук Jezero мають окремі параметри, метрики та повідомлення про роздільність.
- Спокійніший інтерфейс: подробиці DEM і додаткові параметри розкриваються за потреби, початковий каталог науки показує чотири картки з доступом до всіх; на телефоні глобус вміщується по ширині, картка Jezero не перекриває поверхню.
- Регіональний DEM 1513 × 1515, native 20 м, **30.3 × 30.26 км**, 2 292 195 валідних клітинок: точки й A* доступні по всій регіональній 2D-карті. Початковий 5км DEM збережено окремо.
- Метрична шкала Leaflet із реальною марсіанською відстанню; незалежно перевірено, що «3 km» відповідає приблизно 3001.5 м на місцевій широті (похибка display rounding ~0.05%).
- Розширена геологія: 315 вихідних об’єктів, 12 вихідних назв областей. Для браузера спрощені геометрії з допуском 15 м; аналіз відстаней використовує неспрощений експорт.
- Вибір старту/фінішу натисканням карти або координатними полями.
- Явний вибір CTX/HiRISE; без прихованого змішування даних.
- A* у FastAPI: поріг ухилів, штрафи, NoData, diagonal corner checks, snap до центрів клітинок.
- Маршрут і складні сегменти на карті.
- Відстань, набір/спуск, діапазон висот, максимальний ухил і поздовжній градієнт.
- Справжній Plotly-профіль та числова таблиця для доступності.
- Наукові області в межах 200 проєкційних метрів від маршруту, описи, інтерес та USGS-джерела.
- Експорт GeoJSON з явною позначкою **Mars, not WGS84**.
- Стани `no_route`, `blocked_endpoint`, `outside_grid`, `search_limit`, помилки API.
- Скасування застарілих frontend-запитів і очищення результату при зміні параметрів.
- Вибір A/B та повідомлення про помилки біля карти, зокрема зі згорнутою панеллю; обмін A ↔ B, захист від застарілого вимірювання після зміни цілі, скасування очікування відповіді без обіцянки зупинення серверного A*.
- Адаптивний layout і reduced motion.
- Production frontend обслуговується тим самим FastAPI; `/gis-check` збережено окремо.
- README, Docker/Render/Vercel конфігурації, CI, HTML-презентація на шість слайдів, PDF та локальне відео.

- `python -m unittest discover -s tests -v`: **49 тестів пройшли**.
- `python tests/smoke_mvp_browser.py`: успішний реальний CTX та HiRISE A* через production frontend.
- Браузер: маршрут, Plotly, наукові області, експорт GeoJSON, помилки, 375px mobile та landscape.
- Помилок JavaScript page errors немає.
- `no_route` UI-гілка перевіряється mock-відповіддю; реальні disconnected-grid випадки — unit-тестами A*.
- Відео записано автоматизованим Chromium: `artifacts/mvp/mars-explorer-local-demo.webm`.
- `scripts/prepare_runtime_data.py`: SHA-256 дев’яти runtime-масивів перевірено.
- `python tests/smoke_3d_browser.py`: реальний WebGL CTX/HiRISE, збереження маршруту між 2D/3D, масштаб висот, raycast-вибір точки через справжній API, mobile layout.
- `python tests/smoke_globe_browser.py`: реальна глобальна текстура, обертання до іншої півкулі, координати, fullscreen, перехід до Jezero A* та mobile.
- `python tests/smoke_regional_browser.py`: незалежна перевірка Mars scale, реальний ~10км маршрут поза старим AOI, zoom і mobile. Unit/API-тест також будує ~24км маршрут.
- `python tests/smoke_planner_browser.py`: обмін A/B, перехід до карти з демоточок, відкидання затриманого вимірювання, скасування очікування, видимість помилок без панелі й mobile. Затримки/помилки API в цьому регресійному сценарії — контрольовані fixtures, не перевірка наукових розрахунків.
- `scripts/benchmark_routing.py`: медіана п’яти CPU-пошуків, ~2,20–2,26× на трьох зафіксованих сценаріях, однакова оптимальна вартість; не HTTP-бенчмарк і не GPU. Деталі — `docs/routing_performance.md`.

Plotly завантажується окремим lazy chunk (~1,13 МБ до gzip); build попереджає про розмір chunk.
Це не помилка збірки, але на повільному інтернеті профіль може з’явитися із затримкою.

## Наукові обмеження

Модель не сертифікує безпеку. Геологія SIM 3464 має приблизно 100–200 м registration uncertainty.
HiRISE — локальний native window, не весь кратер і не оптична HiRISE-мозаїка.
Метрика близькості областей — проєкційна, не метрова точність геологічної межі.
Профільні похідні й набір висоти залежать від роздільності та шуму DEM.
3D — спрощений display mesh. Проміжки NoData не перекриваються трикутниками; вершини
беруться з вихідних пікселів. Маршрут та маркери мають невеликий візуальний відступ.
Висотне підсилення, освітлення й текстура — лише відображення, не нові вимірювання.
Глобальний Viking-продукт офіційно художньо колоризований, не true-color.
Рельєф глобуса й приблизні маршрути походять з окремого MOLA-продукту;
глобальна роздільність 0,25° не дозволяє оцінювати дрібні перешкоди.
Зелену позначку Jezero збільшено для видимості, вона не позначає розмір кратера.
Повне регіональне покриття висот не означає, що кожна пара точок прохідна:
поріг схилу й перепадів може заблокувати шлях. Для довгих регіональних запитів
діють бюджет пошуку 20 с / 500 000 expansions, з явним `search_limit`.
