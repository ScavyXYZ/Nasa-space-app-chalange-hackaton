# Global Explorer / Mission Control

**Оновлення 15.11:** див. [release_status.md](release_status.md) для поточного
продуктового обсягу. Нижче — початкова архітектура 4 ppd; поточний runtime
має MOLA **16 ppd (0,0625°, ~3,7 км)**. Пошук адаптує coarse stride до
розміру сітки, відстані best зберігаються розрідженим словником.
Додано `/api/expedition` із до чотирьох зупинок, бюджетом 18 с на пошук
етапів, автовибором CTX у Jezero й аналізом геології на вихідних полігонах.
Історичні вимірювання 4 ppd нижче не є поточним бенчмарком.

## Реалізований сценарій

Початковий екран — новий планетарний центр керування:

- глобус із Viking-текстурою або кольоровою топографією MOLA;
- глобальний рельєф, ×1 або явно позначене візуальне підсилення ×10;
- вибір A/B на глобусі чи координатами, обмін, очищення;
- шість оглядових місць, пошук і наведення камери;
- глобальний маршрут, порівняння двох стратегій, перемикання результату;
- профіль із клавіатурним повзунком, відстань, набір висоти, градієнт;
- явне збереження/відновлення плану в localStorage, GeoJSON-експорт;
- збереження поточного глобального плану в пам’яті при переході до Jezero;
- детальна локальна система CTX/HiRISE відкривається окремим режимом.

## Дані та відтворення

Джерело: [NASA PDS / MGS MOLA MEGDR](https://pds-geosciences.wustl.edu/missions/mgs/megdr.html),
підтримуваний PDS4 bundle. Використані продукти v2.0:

- `meg004/megt90n000cb.img`: топографія, MSB signed 16-bit, метри;
- `meg004/megc90n000cb.img`: кількість лазерних спостережень у клітинці.

720 × 1440 клітинок, 0,25°; джерело має довготи 0…360 E, рядки з півночі
на південь. API використовує −180…180 E. Центри: 0,125° E / 89,875° N.
Крок північ–південь ≈14,8 км; схід–захід зменшується з широтою.
Роздільність **не** становить сотні метрів: це компактний MEG004, не MEG128.

Висота відносно ареоїда MOLA GMM3 (mgm1025), degree/order 50. Сфера
для глобальних відстаней має радіус 3 396 000 м із PDS label; локальний
CTX використовує власний радіус 3 396 190 м. Датуми не змішуються.
У цій сітці ~99,12% клітинок містять спостереження. Інші мають
**офіційну інтерполяцію PDS**; API, профіль і статистика маршруту це показують.
Застосунок не створює нових вимірювань для прогалин.

```powershell
python scripts/prepare_global_terrain.py
python scripts/prepare_runtime_data.py
```

Скрипт зберігає SHA-256 оригінальних IMG, labels і runtime-архіву у
`data/processed/global/metadata.json`. Архів `mola_4ppd.npz` (~3,15 МБ)
та текстура зберігаються у звичайному Git, окремо від локальних LFS-масивів.
Під час виконання мережевих запитів до PDS немає.

## Алгоритм

`algorithms/global_routing.py`:

1. Грубий пошук на кожній восьмій вихідній клітинці (~2°).
2. Уточнення на нативній сітці 0,25° у коридорі ±16 клітинок.
3. Якщо немає шляху — коридор ±40, потім пошук на всій нативній сітці
   у межах спільного часового бюджету.
4. Вісім сусідів, циклічні довготи, відбиття рядків через полюс зі
   зсувом довготи на 180°. Усі довжини ребер — великі кола на сфері Марса.
5. Вартість ребра: `length * (1 + slope_weight * segment_grade / 90)`.
   Порогом обмежується поздовжній градієнт між центрами MOLA-клітинок.

Weighted A* використовує коефіцієнт евристики 1,15. Груба сітка —
лише напрямок пошуку: повернені маршрути складаються з нативних клітинок.
**Глобальна оптимальність не гарантується** через weighted search та
обмежений коридор. Повний пошук — fallback після невдалого коридору,
а не перевірка оптимальності успішного маршруту.

12 секунд на пошук із підготовкою коридорів; час перевіряється періодично.
Кожен прохід обмежений 300 000 розгортань. Це не жорсткий HTTP deadline.
Максимум два одночасні глобальні пошуки на процес, далі HTTP 429.
Скасування браузерного очікування не припиняє обчислення на сервері.

Точки прив’язуються до центрів клітинок; API повертає відстані прив’язки.
Відстань маршруту не включає ці зміщення. Одна клітинка повертається як Point.
На полюсах це граф центрів бінів з переходами через полюс, не точна
полярна DEM або моделювання дрібних перешкод.

## Відображення

Браузер отримує сітку 180 × 360 для display mesh; маршрутизація використовує
720 × 1440. Вершини сфери зміщені за MOLA-висотами відносно базової сфери.
Це візуалізація топографії над ареоїдом, не вимір абсолютного радіуса планети.
×10 змінює лише display geometry. Маркери й лінія мають візуальний відступ.
Контурні візерунки карток місць декоративні, не картографічні дані.

Уся компактна глобальна сітка завантажується сервером один раз і кешується.
Потокове завантаження високодетальних глобальних тайлів **не реалізовано**.
CTX/HiRISE не зшиваються автоматично в глобальний маршрут — це окремий
детальний режим, щоб не змішувати роздільність, датуми й значення ухилів.

## API

- `GET /api/global`: походження, роздільність, hash, діапазон висот.
- `GET /api/global/terrain`: display mesh elevations.
- `GET /api/global/elevation?lon=...&lat=...`: висота, counts, interpolation flag.
- `POST /api/global/route`: `start`, `end`, `max_grade_deg`, `slope_weight`.

Наявний `/api/route` залишається точним локальним A*.

## Перевірки та GPU

```powershell
python -m unittest discover -s tests -v
npm --prefix frontend run build
python tests/smoke_mission_browser.py
python tests/smoke_globe_browser.py
python scripts/benchmark_global.py --repeats 3
```

Тести охоплюють полюси, antimeridian, бюджет, заблокований граф,
справжні висоти Olympus/Hellas, суму довжин і нативну суміжність шляху.
Браузерні тести перевіряють реальні маршрути, порівняння, експорт, збереження,
застарілі відповіді, mobile/landscape/tablet і reduced motion.

Обчислення — CPU. WebGL використовує GPU для графіки; GPU routing не реалізовано.
Для цього компактного глобального рівня спершу вимірюється CPU: результати
у `artifacts/global/routing_benchmark.json`, без обіцянок швидкості на іншому хості.
На поточному Windows/Python 3.14.7 медіани трьох запусків для п’яти
зафіксованих сценаріїв становили **18–38 мс**: Tharsis, Olympus–Valles,
перетин ±180°, північного полюса й майже протилежні точки. Це warm-data
час алгоритму з підготовкою та метриками, **не** HTTP latency чи load test.
Високодетальне планетарне покриття потребуватиме інших даних, тайлів і
окремого дослідження compiled CPU/GPU kernels.
